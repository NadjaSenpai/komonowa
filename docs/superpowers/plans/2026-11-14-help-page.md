# ヘルプページ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 初めての人向けの `/help` ページと、その入口（ナビ・編集画面・登録直後・ログイン画面）を作る。

**Architecture:** 中身は `src/pages/HelpPage.tsx` の `HelpContent({ admin })`（状態を持たない表示部品）。`App.tsx` の `/help` はログイン中なら `Layout`、未ログインなら簡単な枠で包む。登録直後の一言は `src/WelcomeNotice.tsx` が `location.state.welcome` を見て出す。

**Tech Stack:** React 19, react-router, vitest（jsdom）。UI テストは追加の依存なしで `react-dom/server` の `renderToStaticMarkup` と `MemoryRouter` で描画して確かめる

**Spec:** docs/superpowers/specs/2026-11-14-help-page-design.md

## Global Constraints

- 節の順と中身は spec の「構成」の通り。説明に出すボタン名は画面の実際の文言と一致させ「」で囲む。です・ます調
- 記法の例の表示側は `renderMarkdown` の出力そのもの
- 「管理者の方へ」は `admin` のときだけ。未ログインでは出さない
- 編集画面の「書き方」は `/help#markdown` を新しいタブ（`target="_blank" rel="noopener"`）
- `npm run check` を通してからコミット

## Review Focus

- 未ログインで `/help` を開いても `/login` に飛ばされない
- 説明のボタン名が実際の画面と違う（「その他」「画像・ファイルを挿入」「チェックをすべて外す」「自分の内容で上書きする」「自分の変更を捨てて最新版を読み込む」「復元」など）
- `#markdown` などページ内リンクで正しい節に飛ぶ（id の付け忘れ）
- 登録直後の一言が、再読み込みやほかの画面からの遷移で出ない
- スマホ幅で記法の表がはみ出さない

### Task 1: ヘルプページと入口

**Files:** Create `src/pages/HelpPage.tsx`, `src/__tests__/help.test.ts`; Modify `src/App.tsx`, `src/pages/AuthPages.tsx`（ログインの案内欄）, `src/pages/ArticleEditPage.tsx`（「書き方」）, `src/styles.css`, `README.md`

**Interfaces:** Produces `HelpContent({ admin }: { admin: boolean })`, `MARKDOWN_EXAMPLES: { label: string; source: string }[]`, `HELP_SECTIONS: { id: string; title: string; admin?: boolean }[]`（目次と見出しの元）, `HelpPage()`（`useAuth` から admin を決めて `HelpContent` を返す）

- [ ] **Step 1: テスト**（help.test.ts）：
  - `HELP_SECTIONS` の各（admin 以外）の見出しと `id` が描画される。`markdown` という id がある
  - `admin: false` では「管理者の方へ」が出ず、`admin: true` で出る
  - `MARKDOWN_EXAMPLES` の各 `source` について、`renderMarkdown(source)` が描画結果に含まれる
  - 例に見出し・太字・取り消し線・リンク・`[[ ]]`・箇条書き・番号・チェックリスト・引用・コード・コードブロック・表・画像がそろう（label で確認）
- [ ] **Step 2: 失敗を確認** `npx vitest run --project ui src/__tests__/help.test.ts`
- [ ] **Step 3: 実装**：`HelpPage.tsx`。`App.tsx` に `/help`（ログイン中は `Layout`、未ログインは brand とログインへのリンクだけの topbar の枠）とナビの「ヘルプ」。ログインの案内欄に「使い方は〈ヘルプ〉」。編集画面の書式ボタンの横に「書き方」リンク。記法の表はスマホ幅で横にはみ出さない（表の枠内でスクロール）。README の機能表に「ヘルプ」行
- [ ] **Step 4: 通過を確認**、`npm run check`
- [ ] **Step 5: コミット** `feat(ui): add a help page for new members`

### Task 2: 登録直後の一言

**Files:** Create `src/WelcomeNotice.tsx`, `src/__tests__/welcome.test.ts`; Modify `src/pages/AuthPages.tsx`（InvitePage の `navigate("/", { replace: true, state: { welcome: true } })`）, `src/pages/ArticleListPage.tsx`

**Interfaces:** Produces `WelcomeNotice()`（`useLocation().state?.welcome === true` のときだけ「ようこそ。はじめての方は〈ヘルプ〉をどうぞ」と「閉じる」を出す）

- [ ] **Step 1: テスト**：`MemoryRouter` の `initialEntries` に `{ pathname: "/", state: { welcome: true } }` で描くと「ようこそ」と `/help` へのリンクが出る。state なし・`welcome` 以外では何も出ない
- [ ] **Step 2: 失敗を確認** `npx vitest run --project ui src/__tests__/welcome.test.ts`
- [ ] **Step 3: 実装**。閉じたら `navigate(".", { replace: true, state: null })` で state を消す（再読み込みや戻るで出直さない）
- [ ] **Step 4: 通過を確認**、`npm run check`
- [ ] **Step 5: コミット** `feat(ui): welcome new members with a pointer to the help page`

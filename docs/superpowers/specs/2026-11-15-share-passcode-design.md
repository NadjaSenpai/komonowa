# 共有のパスワード 設計

## 目的

共有 URL をグループチャットに貼っても、関係ない人には記事を読まれないようにする。合言葉くらいの強さでよい。

## ゴール / ゴールでないもの

- ゴール：共有ごとに、任意で 6 桁の数字のパスワード（合言葉）を付けられる。付けた共有は、パスワードを入れた人だけが本文・画像・添付を見られる
- ゴール：メンバーは共有の欄でいつでもパスワードを見直し、作り直し、外せる
- ゴール：総当たりで当てられない（回数制限）
- ゴールでない：メンバーが好きな文字列を決めること、共有相手ごとに違うパスワード、パスワードの有効期限
- 失敗とみなすもの：パスワードを入れていない人が、画像や添付の URL を直接開いて見られる。パスワードを作り直した・外した・共有を止めたのに、前に入れたブラウザで見え続ける（外した場合は誰でも見えてよい）。ログイン中のメンバーが共有ページを開いたら、アプリからログアウト扱いになる

## 方式（検討したもの）

| 案 | 内容 | 採否 |
| --- | --- | --- |
| A | 6 桁の数字を自動で作り、メンバーが見直せる形で保存 | **採用**（利用者が選択）。使い回しの心配がなく、別の手段で伝えやすい |
| B | メンバーが決めたものをハッシュで保存 | 不採用。忘れたら付け直すしかない |
| C | メンバーが決めたものをそのまま保存 | 不採用。普段のパスワードが入るとそのまま残る |

## 決めたこと

- **データ**（マイグレーション `0009`）：`article_shares` に `passcode TEXT`（NULL ならパスワードなし）。間違いの記録 `share_passcode_failures(article_id REFERENCES articles(id) ON DELETE CASCADE, created_at)`
- **作り方**：`crypto.getRandomValues` で 000000〜999999 を偏りなく選ぶ（6 桁、先頭の 0 も残す）
- **メンバーの操作**（要ログイン、メンバー・管理者とも）
  - 記事の `share` に `passcode: string | null` を足す
  - `POST /api/articles/:id/share/passcode` → 新しいパスワードを作る（付けるのも作り直すのも同じ）。共有していなければ 404。応答は `{ share }`
  - `DELETE /api/articles/:id/share/passcode` → 外す。応答は `{ share }`
  - 作り直したら、間違いの記録も消す
- **管理者**：`GET /api/admin/shares` の各行に `has_passcode: boolean`。管理画面の一覧に「パスワードあり」
- **共有ページの API**
  - パスワード付きの共有は、鍵（下記）がなければ `GET /api/share/:token` と添付を **403** `{ error: "パスワードを入れてください", needsPasscode: true }` で断る（401 にすると、ログイン中のメンバーの画面がログアウト扱いになるため）
  - `POST /api/share/:token/unlock` `{ passcode }`：
    - 15 分以内の間違いが 5 回以上なら 429「間違いが続いたため、15分ほど待ってからもう一度試してください」（正しくても）
    - 違えば間違いを記録して 403 `{ error: "パスワードが違います", needsPasscode: true }`
    - 合えば間違いの記録を消し、鍵のクッキーを付けて `{ ok: true }`
    - パスワードのない共有なら `{ ok: true }`（クッキーなし）
    - 共有が見つからなければ、ほかと同じ 404
  - **鍵のクッキー**：名前 `share_key`、値は `SHA-256(token + ":" + passcode)`、`Path=/api/share/<token>`、`HttpOnly; Secure; SameSite=Lax; Max-Age=30日`。サーバーは保存しない。パスワードを作り直すと値が合わなくなり、入れ直しになる。比較は時間が一定の比較で行う
  - パスワードの比較も時間が一定の比較で行う
- **共有の欄（記事画面）**：共有中のとき、
  - パスワードなし：「パスワードを付けると、URL を知っていても、パスワード（6桁の数字）を入れた人しか読めなくなります」と「パスワードを付ける」
  - パスワードあり：パスワードを大きく表示し、「URL とは別に伝えてください」。「作り直す」（確認：「作り直すと、前のパスワードで見ていた人も入れ直しになります」）と「外す」（確認：「外すと、URL を知っている人は誰でも読めるようになります」）
- **共有ページ**：`needsPasscode` なら「この記事はパスワードで守られています。共有した人から聞いた6桁の数字を入れてください」と入力欄（数字キーボード、自動入力なし）と「開く」。合ったら本文を読み込み直す
- **ヘルプと README**：共有の節にパスワードのことを足す

## わたしの判断（直してよい）

- 回数制限は共有ごとに 15 分で 5 回。6 桁なら、制限の下で当てるには何年もかかる
- 鍵のクッキーは 30 日。共有を止めたら記録ごと消えるので、クッキーが残っても 404
- パスワードはメンバーなら誰でも見られる（管理者の一覧には「あり／なし」だけ出す）

## テスト

- 権限：パスワードの付け外しは未ログイン 401、メンバー・管理者可。共有していない記事は 404
- 付けると 6 桁の数字。作り直すと変わる。記事の GET に出る。外すと null
- 鍵なしだと本文も添付も 403 `needsPasscode`。違うパスワードは 403。正しいと Set-Cookie（Path・HttpOnly・Secure・SameSite・Max-Age）が付き、そのクッキーで本文と添付が読める
- 作り直すと古いクッキーでは 403。外すとクッキーなしで読める。止めると 404
- 5 回間違えると、正しいパスワードでも 429。作り直すと解ける
- 管理者の一覧に `has_passcode`
- UI：見た目の部品は手で確認（テストは API で行う）

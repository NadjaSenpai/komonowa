# B2 定期バックアップ

## 目的と合意事項

Cloudflare のアカウントにアクセスできない場合にも、記事・履歴・添付・アイコンを復元できるようにする。
GitHub Actions で毎月1・8・15・22日に取得し、非公開 B2 バケット `komonowa-backups`（US West）に24世代を保存する。
保存量は実測して無料保管枠10GBを超えないか確認する。

## 方式

既存のバックアップスクリプトを Actions から実行する。Workers/Workflows 方式は既存CLI処理の移植が必要なので今回は採用しない。
時刻は実装上の判断として JST 09:23。定刻ちょうどの混雑を避ける。手動実行も可能にする。
デプロイと同じ concurrency group を使い、マイグレーションと同時に動かさない。

SQLをローカルSQLiteへ読み込んでファイル一覧を生成し、そのSQLが参照するR2オブジェクトを取得する。
取得中の削除による欠落は成功扱いにせず失敗させる。ユーザーの書き込みは停止しないため、D1/R2全体の原子的なスナップショットは保証しない。

tar.gz を GPG の AES256 で暗号化する。パスフレーズは新しい Actions Secret `BACKUP_PASSPHRASE` に保存し、利用者が別途保管する。
B2キーは登録済みの `B2_ACCESS_KEY_ID` / `B2_SECRET_ACCESS_KEY` を使う。
暗号文をアップロード後、取得し直して SHA-256 を比較する。検証成功後だけ古い世代をバージョンID指定で完全削除する。
削除範囲は専用の `komonowa/backup-<日時>.tar.gz.gpg` 形式に限定する。

## 運用と制約

復号・SQL/R2復元・確認の手順を operations.md に記載する。
失敗は Actions の失敗として通知設定で確認する。未実行の外部監視は今回は追加しない。担当者が月1回、最終成功日時と容量を確認する。
mainへの反映、追加Secretの登録、初回の実バックアップ・復元確認が終わるまで稼働済みとは扱わない。

# 履歴の差分表示 設計

## 目的

変更履歴で、ある版が 1 つ前の版から何を変えたかを一目でわかるようにする。今は版の全文を表示するだけで、変更点は目で見比べるしかない。復元するか判断するときや、だれが何を直したか確かめるときに使う。

## ゴール / ゴールでないもの

- ゴール：各版（第 2 版以降）で、1 つ前の版との差分を表示できる
- ゴール：本文は行ごとの追加・削除がわかり、書き換えた行は行内の変わった部分もわかる
- ゴール：タイトルとタグの変更もわかる
- ゴールでない：任意の 2 つの版を選んで比べる（利用者が「1 つ前と比べられればいい」と判断）、差分からの部分的な復元、サーバー側での差分計算
- 失敗とみなすもの：差分の表示が本文を HTML として解釈する（原文は文字として出す）、長い記事で画面が固まる

## 方式（検討したもの）

| 案 | 内容 | 採否 |
| --- | --- | --- |
| A | 行単位の差分を `src/lineDiff.ts` に自前で書く（LCS） | **採用**。数十行で済み、テストしやすい |
| B | `diff` ライブラリを入れる | 不採用。依存が増え、この用途には大きい |
| C | 任意の 2 版を選んで比べる | 不採用。利用者が 1 つ前との比較で足りると判断 |

## 決めたこと

- 履歴の表の各行に「差分」ボタン（第 1 版には出さない）。押すと、その版と 1 つ前の版を既存の API（`GET /api/articles/:id/revisions/:version`）で取り、表の下に差分を出す。「表示」と同じ場所に出し、どちらか一方だけを出す
- 本文は Markdown の原文を行ごとに比べる。削除行は赤、追加行は緑。変わっていない行は変更の前後 3 行だけ残し、それ以外は「… n 行」にたたむ
- 削除行と追加行が隣り合って同じ数だけ並ぶとき、対になる行どうしで文字単位の差分をとり、変わった部分を濃く塗る〔作り手の判断：日本語は 1 段落が 1 行になりがちなため〕
- タイトルが変わったら「タイトル：旧 → 新」、タグが変わったら「タグ：+追加 −削除」を本文の差分の上に出す
- 本文が同じなら「本文の変更はありません」と出す
- 差分は React の要素として描き、`dangerouslySetInnerHTML` は使わない

## 作り手に任せること

- LCS の実装方法と、長い本文への対処（行数の積が大きいときは文字単位の差分を省くなど）
- 見た目の細部（色は既存のトークンに合わせる）

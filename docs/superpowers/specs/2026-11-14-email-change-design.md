# メールアドレスの変更（短い設計）

## 目的

メンバーが自分のメールアドレスを変えられるようにする。今はアカウント画面で表示名・アイコン・パスワードしか変えられない。

## 決めたこと

- **本人だけ**が変えられる。管理者がほかの人のアドレスを変えられると、所有者のアドレスを書き換えて再設定メールを横取りでき、所有者の保護（2026-11-14-owner-design.md）が破れるため。
- **申し込み**：`POST /api/auth/email`（ログイン中の本人）。`{ email, currentPassword }`。
  - パスワード違い 403「現在のパスワードが正しくありません」。今と同じアドレス 400「今のメールアドレスと同じです」。ほかの人が使用中 409「このメールアドレスはすでに使われています」。
  - 新しいアドレスに確認メール（HTML＋文字）を送り、送れたら記録する（送信失敗は 502、何も変わらない）。リンクは `<origin>/email#<token>`、24 時間有効、一回限り。
  - 同じ人の確認待ちの申し込みは取り消す。応答は `201 { expiresAt }`（トークンは含めない）。
- **確定**：`POST /api/auth/email/confirm` `{ token }`。ログイン不要（別の端末でメールを開いても確定できる）。
  - 無効・期限切れ・使用済み・取り消し済み、または本人が無効化されていれば 410「リンクが無効か期限切れです。もう一度アカウント画面から申し込んでください」。
  - その間にアドレスがほかの人に使われていれば 409（上と同じ文言）。
  - アドレスを切り替え、まだ使っていないパスワード再設定リンクを無効にする。セッションはそのまま。
  - 古いアドレスに「メールアドレスが変更されました。身に覚えがなければ管理者に連絡してください」を送る。送れなくても変更は取り消さず、ログに残す。
  - 応答 `{ email }`（新しいアドレス）。
- **保存**：新しいテーブル `email_changes(token_hash PK, user_id, new_email, expires_at, used_at, revoked_at, created_at)`（マイグレーション `0006`）。`auth_tokens` は種類の CHECK 制約があり、種類を足すにはテーブルの作り直しが要るため使わない。
- **画面**：アカウント画面に「メールアドレスの変更」欄（今のアドレス、新しいアドレス、現在のパスワード、「確認メールを送る」）。送ったら「○○ に確認メールを送りました。メールのリンクを開いて確定すると変更されます（24時間有効）」。確認ページ `/email` は「変更を確定する」ボタンで確定し（開いただけでは確定しない。メールソフトのリンク検査や開発時の二重実行で、使う前にトークンが消費されるのを防ぐ）、「メールアドレスを ○○ に変更しました」。ログイン中なら画面の利用者情報も新しいアドレスにする。

## 作らないもの

- 管理者がほかの人のアドレスを変える機能。変更の取り消し機能（古いアドレスのお知らせは管理者への連絡を促すだけ）。

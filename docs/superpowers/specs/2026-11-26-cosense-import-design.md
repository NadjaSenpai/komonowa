# Cosense（旧 Scrapbox）からの取り込み 設計

## 目的

管理者が、Cosense プロジェクトから komonowa へ記事を引っ越せるようにする（当初はメンバーのだれでも使える設計だったが、2026-11-26 に管理者だけに変更。入口をサイト管理にまとめるため）。Cosense の「Export Pages」で書き出した JSON を読み込み、取り込むページを選んで、komonowa の記事にする。

## ゴール / ゴールでないもの

- ゴール：管理者が、Cosense のエクスポート JSON から記事を取り込める
- ゴール：取り込むページを一覧から選べる（チェック式）
- ゴール：Cosense の記法を komonowa の Markdown に変換し、見た目と意味がおおむね保たれる（リンクはリンク、太字は太字、箇条書きは箇条書き、画像は画像）
- ゴール：公開されている画像は komonowa の添付として保存し、Cosense 側が消えても表示できる
- ゴール：一覧の並びが Cosense での新しさのとおりになるよう、作成日・更新日を引き継ぐ
- ゴールでない：Cosense との同期・再取り込みでの更新、ページの編集履歴（行ごとの書き手・日時）の再現、Cosense のユーザーと komonowa のユーザーの対応付け、ほかのサービス（Notion など）からの取り込み、取り込み済みかどうかの記録
- 失敗とみなすもの：
  - ほかの人の既存記事が書き換わる
  - Cosense の太字 `[[文字]]` が komonowa のリンクに化ける
  - 任意の URL をサーバーに取りに行かせられる（サーバーが踏み台になる）
  - 取り込みが途中で失敗して、本文が中途半端な記事や、どこにも属さない添付が残り続ける

## 方式（検討したもの）

| 案 | 内容 | 採否 |
| --- | --- | --- |
| A | 記法の変換はブラウザ（`shared/` の純粋関数）。選んだページを新しい取り込み API に1ページずつ送り、サーバーが画像の保存と記事の作成をまとめて行う | **採用**（利用者が選択） |
| B | JSON を丸ごとサーバーに送り、サーバーで変換・保存まで全部行う | 不採用。大きいプロジェクトは1リクエストの時間・外部アクセス数の上限に届き、結局分割が要る |
| C | 既存の `POST /api/articles` を使い、画像だけ新しい API で保存する | 不採用。既存 API は日付を引き継げず、記事と画像が別リクエストになり途中失敗で中途半端な記事が残る |

画像はブラウザから Gyazo などへ取りに行くと CORS で止まるため、サーバーで取る。

## 決めたこと

### 入口と画面

- 画面は `/import/cosense`（管理者だけ）。入口はサイト管理（`src/pages/AdminPage.tsx`）の「Cosense から取り込む」と、ヘルプの管理者向けの節
- 流れ：
  1. JSON ファイルを選ぶ（ブラウザで読むだけ。サーバーへは送らない）
  2. ページの一覧を出す。各行に、チェック・タイトル・更新日・本文の行数・画像の数
  3. 実行すると1ページずつ送り、進み具合（n / 全体）を出す
  4. 終わったら結果を出す：取り込めた記事（リンク付き）、取り込めなかったページと理由、保存できなかった画像の件数とその記事
- 一覧の初期状態は全部チェック。ただし次のページはチェックを外し、理由を表示する
  - **同じタイトルの記事がすでにある**：行にタイトルの入力欄を出す。名前を変えて重複がなくなればチェックできる。上書きはしない
  - **同じ JSON の中でタイトルが重なる**（komonowa のタイトル比較 `titleKey` で同じになる）：同上
  - 本文が上限（200,000 文字）を超える：取り込めない
- 「すべて選ぶ / すべて外す」を付ける
- 既存記事との重複は、読み込んだ時点でサーバーに問い合わせる（下の `POST /api/import/cosense/check`）。実行時にも記事作成の時点で確かめ、重複なら 409 でそのページは失敗として結果に出す

### JSON の形

- Cosense のエクスポートは2種類あり、どちらも受け付ける
  - メタデータ付き：`pages[].lines[]` が `{ text, created, updated, userId }` の配列
  - メタデータなし：`pages[].lines[]` が文字列の配列
- 使うのは `pages[].title`、`pages[].created`、`pages[].updated`（秒）と、各行の `text` だけ。`users`、`views`、行ごとの `userId` などは使わない
- `lines` の1行目はタイトルと同じなので本文から除く
- 形が違う JSON は「Cosense のエクスポートファイルではないようです」と出して止める

### タイトル

- 半角の `[` `]` は komonowa のタイトルに使えないので、全角の `［` `］` に置き換える（一覧に置き換え後のタイトルを出す）
- 200 文字を超えるタイトルは切る

### 記法の変換（`shared/cosense.ts`、純粋関数）

1行ずつ見て Markdown にする。komonowa の Markdown は `breaks: true` なので、改行はそのまま改行になる。

| Cosense | komonowa | メモ |
| --- | --- | --- |
| 行頭の空白・タブ n 個（n ≥ 1） | 深さ n の箇条書き `- `（字下げは 2 文字 × (n−1)） | 空白とタブは同じ 1 段 |
| `[ページ名]` | `[[ページ名]]` | `［］` に置き換える前の名前のリンクでも、取り込んだ記事のタイトルと同じ置き換えをする |
| `[/プロジェクト/ページ]`、`[/プロジェクト]` | `https://scrapbox.io/...` へのリンク | 別プロジェクトは komonowa の記事にしない |
| `[[文字]]` | `**文字**` | 太字。**リンクにしない** |
| `[* 文字]` | `**文字**` | |
| 行全体が `[** 文字]` / `[*** 文字]` 以上 | `### 文字` / `## 文字` | アスタリスク 4 個以上は `##` |
| `[/ 文字]`、`[- 文字]`、`[*/ 文字]` などの組み合わせ | `*文字*`、`~~文字~~`、組み合わせ | |
| `[URL]`（画像：拡張子が png/jpg/jpeg/gif/webp、または Gyazo） | `![](URL)` | 画像の保存は下の「画像」 |
| `[URL]`（YouTube） | URL だけの行 | komonowa は URL だけの行を動画にする |
| `[URL]`（それ以外） | `<URL>` | |
| `[文字 URL]` / `[URL 文字]` | `[文字](URL)` | |
| `#タグ`、`#[タグ 名]` | 本文には文字のまま残し、記事のタグにも足す | 行がタグだけなら本文から消す。タグは komonowa の上限（20 個・40 文字・カンマ不可）に収める |
| `[名前.icon]`、`[名前.icon*3]` | 消す | 〔作り手の判断：消すか名前を残すか〕 |
| `code:ファイル名` ＋ 字下げした行 | ` ```言語 ` のコードブロック | 言語は拡張子から（分からなければ空） |
| `table:名前` ＋ 字下げした行（タブ区切り） | Markdown の表 | 1 行目を見出しにする |
| `> 文字` | `> 文字` | |
| `` `コード` `` | そのまま | |
| `$ コマンド`、`% コマンド` | インラインコード | |
| `[$ 数式]` | インラインコード | |

- 変換の中の記号（`*`、`_`、`<` など）は、Markdown として誤って解釈されないよう必要に応じてエスケープする
- 変換できない・知らない記法は文字のまま残す（消さない）

### 画像

- サーバーが取りに行くのは次の画像だけ（許可リスト）。それ以外の URL は Markdown の画像のまま残し、komonowa は外部の画像として表示する（CSP は `img-src https:` を許可済み）
  - `https://scrapbox.io/files/<id>.<拡張子>`、`https://gyazo.com/<id>`、`https://i.gyazo.com/<id>.<拡張子>`
  - Gyazo のページ URL（`gyazo.com/<id>`）から画像の URL を得る方法は作り手が決める（`i.gyazo.com` の拡張子の推測、または Gyazo の oEmbed）
- 転送は最大 3 回までたどり、転送先は https に限る。ホストは問わない〔作り手の判断：scrapbox.io/files は別ホストのストレージへ転送しうる。最初の URL が許可リストに限られるので、サーバーが任意の URL の踏み台にはならない〕
- 取った画像は既存の添付と同じ検査を通す：拡張子と先頭バイトの一致（`contentMatches`）、10MB 以下、png/jpg/gif/webp のみ
- 保存は既存の添付と同じ R2 キー・`attachments` 行にする。一覧用の小さい版（`.thumb`）はサーバーでは作れないので作らない（一覧は元の画像を縮めて出す。既存の挙動）
- 取れなかった画像（非公開プロジェクトでログインが要る、消えている、形式が違う、大きすぎる）は URL のまま残し、結果に件数を返す
- 1 ページの画像は 50 個まで取りに行く。それを超えた分は URL のまま残す

### API

- `POST /api/import/cosense/check`（要ログイン）
  - 入力：`{ titles: string[] }`（最大 5,000 件）
  - 出力：`{ taken: string[] }`（ごみ箱にない既存記事と `titleKey` が同じもの）
- `POST /api/import/cosense/pages`（要ログイン）1 ページ分
  - 入力：`{ title, body, tags, created, updated }`。`body` は変換済みの Markdown（保存したい画像は `![](URL)` のまま）。`created` / `updated` はミリ秒
  - 検証は既存の記事作成と同じ（タイトル・本文・タグの上限、タイトルの `[ ]` 不可）。日付は 2000-01-01 以降かつ現在以下、`created <= updated`。範囲外なら現在時刻
  - 処理：本文の許可リスト内の画像を取りに行く → 添付として保存（記事なしの下書き状態）→ 本文の URL を `/api/attachments/<id>` に書き換える → 既存の記事作成と同じ書き込み（`writeStatements`、表紙の画像の選定を含む）に、添付のひもづけを足して 1 つのバッチで書く
  - 記事の `created_at` / `updated_at` と 1 版目の履歴の日時は、入力の日付にする。作成者・更新者・履歴の編集者は取り込んだ本人。履歴の種類は `create`
  - 出力：`{ article: { id, title }, images: { saved, failed } }`（201）。同名の記事があれば 409
  - 記事の書き込みに失敗したとき、保存済みの添付は下書きのまま残る。期限（`DRAFT_TTL_MS`）を過ぎた下書き添付を消す `purgeExpiredDrafts`（`worker/routes/attachments.ts`）は、今は添付のアップロードのついでにしか動かない（日次の cron は添付を消さない）。取り込み API でも同じ関数を `waitUntil` で呼ぶ〔作り手の判断〕
  - 日付を引き継ぐため、記事の INSERT と `writeStatements` に渡す日時を、入力の日付にできるようにする（記事作成の既存の動きは変えない）
  - 画像は 1 枚ずつ順に取って保存する（メモリと外部アクセス数を抑える。50 枚でも 1 リクエストのサブリクエスト上限 1000 に収まる）〔作り手の判断〕
- どちらも管理者だけ（`requireAdmin`）。メンバーは 403

### 共通

- 1 ページずつ順に送る（並列にしない）。途中でページを閉じたら、それまでに取り込んだ記事は残る
- 取り込んだ記事はふつうの記事と同じ（編集・履歴・共有・ごみ箱）

## テスト

- `shared/cosense.ts`：上の表の記法ごと、組み合わせ、`[[文字]]` が太字になること、メタデータあり・なしの JSON
- API：未ログイン 401、メンバー・管理者で作成できること、日付の引き継ぎ、同名で 409 と既存記事が変わらないこと、許可リスト外の URL を取りに行かないこと、取れない画像が URL のまま残ること、`check` の結果。画像の取得は fetch をモックする
- 画面：選択の初期状態（同名・JSON 内の重複のチェックが外れる）、名前を変えるとチェックできること

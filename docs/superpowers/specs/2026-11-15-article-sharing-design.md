# 記事の外部共有 設計

## 目的

メンバーが、手順書などの記事を **1本ずつ**、komonowa のアカウントを持たない友達に見せられるようにする。広く公開するための機能ではない。

## ゴール / ゴールでないもの

- ゴール：共有を ON にした記事だけを、推測できない共有専用 URL でログインなしに読める
- ゴール：共有を止めたら、その URL では**すぐ**見えなくなる。もう一度 ON にしたら新しい URL になり、前の URL は無効のまま
- ゴール：メンバーなら誰でもどの記事でも共有を ON/OFF できる。管理者は共有中の記事を一覧で見て止められる
- ゴール：検索エンジンや AI の収集ボットに載せない意思表示をする（noindex・robots.txt）
- ゴールでない：共有相手のコメントや編集、パスワード付き共有、有効期限、閲覧数の記録、ブログのような公開、記事以外（タグ・一覧）の共有
- 失敗とみなすもの：共有していない記事や、ほかの記事の添付が共有 URL から取れる。止めたのに見える。共有ページからメンバーの名前・メールアドレスが分かる

## 方式（検討したもの）

| 案 | 内容 | 採否 |
| --- | --- | --- |
| A | 記事ごとに共有専用のランダムな URL を発行。止めたら記録を消す | **採用**（利用者が選択） |
| B | 記事に公開の印を付けて記事 URL のまま見せる | 不採用。ID はあちこちに出ていて、OFF→ON で前に知った人も見られる |
| C | ON にした時点のコピーを書き出す | 不採用。直すたびに書き出し直しが要り、画像のコピーも重い |

## 決めたこと

- **データ**：`article_shares`（`article_id` 主キー、`token` 一意、`created_by`、`created_at`）。マイグレーション `0008`。1記事に共有は1つ。トークンは `randomToken()`（推測できない長さ）。共有中はメンバーが URL を見直せるよう、トークンはそのまま保存する（アカウントの鍵ではなく、記事本文と同じ DB にあるため）
- **URL**：`/s/<トークン>`（画面）。API は `/api/share/<トークン>`
- **共有の操作（要ログイン、メンバー・管理者とも）**
  - `GET /api/articles/:id` の応答に `share: { url, created_at, created_by_name } | null` を足す
  - `POST /api/articles/:id/share` → 共有を始める。すでに共有中なら今の共有をそのまま返す（201 / 200）
  - `DELETE /api/articles/:id/share` → 共有を止める（記録を消す）
  - ごみ箱の記事は共有を始められない（404）
  - 記事をごみ箱に入れたら共有も止める（記録を消す）。ごみ箱から戻しても共有は止まったまま
- **管理者**：`GET /api/admin/shares`（記事タイトル・始めた人・日時）と `DELETE /api/admin/shares/:articleId`。管理画面に「共有中の記事」節を足す
- **共有ページの API（ログイン不要）**
  - `GET /api/share/:token` → `{ title, body, updated_at }` だけ。書いた人・タグ・版・添付一覧・リンク情報は返さない
  - `GET /api/share/:token/attachments/:id` → その記事に添付されたファイルだけ。ほかの記事の添付や下書き添付は 404
  - 記事がごみ箱にあるとき、共有が消えているとき、トークンが違うときは、どれも同じ 404「共有が見つかりません。共有が止められたか、URL が違います」
  - 応答に `X-Robots-Tag: noindex, nofollow, noarchive, noai, noimageai` と `cache-control: no-store`（止めたら即座に見えなくするため。添付も no-store）
- **共有ページの画面**（`/s/:token`、ログイン不要、上のナビなし）
  - 小さく「komonowa で共有された記事」、タイトル、最終更新日、本文
  - 本文の `/api/attachments/<id>` は `/api/share/<トークン>/attachments/<id>` に読み替えて表示する
  - 記事リンク `[[ ]]` はただの文字として出す
  - チェックリストは印の表示だけ（付け外しはしない）
  - 見つからなければ上の 404 の文言
- **記事画面の操作**：記事画面の操作に「共有」ボタン。押すと共有の欄が開き、
  - 共有していないとき：「共有すると、URL を知っている人はログインなしでこの記事を読めます。書いた人の名前やタグは表示されません」と「共有を始める」
  - 共有中：URL、「コピー」、「共有を止める」、「〇〇さんが △△ に共有を始めました」。止めるときは確認を出す
  - 共有中の記事には、タイトルの近くに「共有中」の印
- **検索エンジン・AI**：`public/robots.txt` で全ボットを Disallow（AI の収集ボットも名前を挙げて）。`index.html` の meta robots に noarchive・noai・noimageai を足す。README・運用メモに、Cloudflare の「AI ボットをブロック」の設定を勧める一文と、「これらは行儀のよいボットにしか効かず、守りの本体は URL を知られないこと」を書く
- **ヘルプ**：ヘルプページに「記事を共有する」節を足す

## わたしの判断（直してよい）

- 共有の記録はトークンをそのまま保存する（ハッシュにすると、共有中に URL を見直せない）
- 止めると記録を消す（履歴は残さない）
- 共有ページは常に最新版を出す
- ごみ箱に入れたら共有を止める（戻したときに、忘れていた共有が勝手に復活しないように）

## 作る人に任せること

- 共有ページの見た目（記事画面の本文の見た目に合わせる）、「コピー」の実装（Clipboard API、使えないときは選択状態にする）

## テスト

- 権限：共有の開始・停止は未ログイン 401、メンバー可、管理者可。管理者の一覧・停止はメンバー 403
- 共有ページ：ログインなしで読める。止めたら 404。もう一度始めると新しいトークンで、古いトークンは 404。ごみ箱に入れたら 404 で、戻しても 404（共有は止まったまま）
- 応答に名前・タグ・版などが含まれない。X-Robots-Tag と no-store が付く
- 添付：その記事の添付は読める。ほかの記事の添付・下書き添付・共有していない記事の添付は 404
- 記事の完全削除で共有の記録も消える
- UI：本文の添付 URL の読み替えと、記事リンクを文字にする処理

# 記事一覧のサムネイル 設計

## 目的

記事に画像が貼ってあるとき、一覧のサマリの横に小さな画像を出して、一覧を眺めるのを楽しくする。スマホで重くならないことを優先する。

## ゴール / ゴールでないもの

- ゴール：本文の最初の画像（添付画像）を、一覧で小さく表示する
- ゴール：一覧では小さい版（サムネイル）だけを読み、元の画像（最大 10MB）は読まない
- ゴールでない：外部サイトの画像（CSP でもともと表示できない）、画像以外の添付のプレビュー、サムネイルの手動選択
- 失敗とみなすもの：一覧がスマホで目に見えて重くなる。権限のない人にサムネイルが見える。記事や添付を消したのにサムネイルが R2 に残る

## 方式（検討したもの）

| 案 | 内容 | 採否 |
| --- | --- | --- |
| A | 元の画像を CSS で小さく表示 | 不採用。写真が多いとスマホで重い |
| B | アップロード時にブラウザで小さい版を作り、一緒に保存 | **採用**（利用者が選択）。アイコン画像の縮小と同じ仕組み |
| C | Cloudflare の画像変換で配信時に縮める | 不採用。別機能の有効化と課金、非公開配信との組み合わせの調べ直しが要る |

## 決めたこと

- **作る**：画像（PNG・JPEG・WebP・GIF）を添付するとき、ブラウザで長辺 400px 以内に縮めた WebP（作れないブラウザでは JPEG。透明部分は白）を作り、同じアップロードの `thumb` 欄で送る。元の画像が小さくても作る。作れなかったり 200KB を超えたりしたら `thumb` なしで送る（添付自体は止めない）
- **受ける**：サーバーは `thumb` を、元のファイルが画像のときだけ受け付ける。WebP・JPEG・PNG のどれかであることを先頭バイトで確かめ、200KB を超えたら 413。R2 のキーは元のキー + `.thumb`。`attachments` に `thumb_key` 列を足す（マイグレーション `0007`）
- **配る**：`GET /api/attachments/:id/thumb`。権限と見えるかどうかは元の添付と同じ判定。小さい版がない・R2 に見つからないときは元の画像を返す（すでに貼ってある画像と、バックアップから戻した場合はこれになる）
- **選ぶ**：一覧 API は記事ごとに `cover`（添付 ID か null）を返す。本文の中で最初の `![...](/api/attachments/<id>)` のうち、その記事の添付で画像のもの。保存時ではなく一覧を返すときに本文から探す（作成・編集・復元・添付の削除で列を直し忘れないため）
- **消す**：添付の削除、記事の完全削除、期限切れの下書き添付の掃除で、小さい版も R2 から消す
- **見せる**：一覧の各記事の右側に正方形で表示（スマホ 96px、広い画面 160px、`object-fit: contain`（切らずに全体を収める）、`loading="lazy"`、`alt=""`）。押すと記事を開く（抜粋と同じリンク、読み上げとキーボードの移動からは外す）
- バックアップには小さい版を含めない（なくても元の画像で代わりに出るため）

## わたしの判断（直してよい）

- 長辺 400px：表示は最大 96px 四方なので、高精細の画面でも足りて、1枚数十 KB に収まる
- GIF は最初のコマだけの静止画になる
- 一覧の位置は右側。タイトルと抜粋の読み始めをそろえたままにするため

## テスト

- API：画像に `thumb` を付けて添付すると `/thumb` で小さい版が返る。`thumb` なしなら元の画像が返る。画像以外の添付に `thumb` を付けると 400。WebP・PNG 以外や 200KB 超は断る。未ログイン 401。ごみ箱の記事の添付は元の添付と同じ扱い
- 一覧 API：最初の画像の添付 ID が `cover` に入る。画像以外のリンクや、ほかの記事の添付、外部の画像は選ばない。画像がなければ null
- 削除：添付の削除・記事の完全削除・下書きの掃除で `.thumb` も消える
- UI：縮小の関数が長辺 400px 以内になる

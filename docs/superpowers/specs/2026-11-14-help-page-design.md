# ヘルプページ 設計

## 目的

使う人を増やしたい。招待メールから初めて来た人が、管理者に聞かずに記事を読み・探し・書けるところまで行けるようにする。招待する人には記号（Markdown）が苦手な人もいるので、**ボタンで書ける説明を先に**置き、分かる人向けに **Markdown 記法の早見表**を後ろに置く。

## ゴール / ゴールでないもの

- ゴール：初めての人が迷う点（ボタンでの書き方、`[[ ]]` リンク、チェックリスト、履歴、添付、困ったときの連絡先）を一か所で読める
- ゴール：機能と同じリポジトリで管理し、機能を変えたら同じコミットでヘルプも直せる
- ゴールでない：チーム独自の書き方ルール（それは普通の記事として人が書く）
- ゴールでない：利用者がヘルプを編集できること、検索、多言語
- 失敗とみなすもの：画面と食い違う説明（ボタン名・場所が実際と違う）。記法の例の表示が実際の記事表示と違う

## 方式（検討したもの）

| 案 | 内容 | 採否 |
| --- | --- | --- |
| A | アプリに組み込んだ `/help` ページ（React） | **採用**。コードと一緒に直せて古くなりにくい。記法の例を記事表示と同じ `renderMarkdown` で描ける |
| B | 「使い方」記事を初期データとして入れる | 不採用。機能が変わっても自動で直らず、誰でも消せる。初期データ投入の仕組みも要る |
| C | A + B | 作るものは A と同じ。チームのルール記事は必要になったら人が書く |

## 決めたこと

- ルート `/help`。中身は `src/pages/HelpPage.tsx`
- 構成（この順）：
  1. はじめに（komonowa でできることを 2〜3 行）
  2. 記事を読む・探す（キーワード検索は空白区切りで全部を含む記事、タグの複数選択、目次、「このページにリンクしているページ」）
  3. 記事を書く（ボタンで）：「新しい記事」→ タイトル・タグ・本文 →「保存」。書式ボタン（見出し・太字・リンク・箇条書き、残りは「その他」の中）、押すと記号が入ること、Ctrl+Z で取り消せること、「プレビュー」タブ、ファイルの差し込み（ボタン・貼り付け・ドラッグ＆ドロップ、10MB まで）
  4. ほかの記事へのリンク（「記事リンク」ボタン / `[[タイトル]]`。まだない記事は薄く表示され、押すとそのタイトルで作れる。タイトルの重複不可、半角 `[` `]` 不可で全角［］は可）
  5. チェックリスト（表示画面でクリックして付け外し、状態はそのブラウザにだけ保存、「チェックをすべて外す」）
  6. 履歴と復元、同時に編集したとき（上書きするか、自分の変更を捨てて最新版を読み込むか選べる）
  7. 削除とごみ箱（メンバーはごみ箱へ移すだけ、戻すのは管理者）
  8. アカウント（表示名、アイコン、メールアドレス、パスワード）
  9. 困ったとき（パスワードを忘れたら管理者に再設定メールを頼む、メールが届かないときは迷惑メールフォルダ）
  10. Markdown 記法（分かる人向け）：「こう書く」と「こう表示される」を並べた表。表示側は `renderMarkdown` で描く（見出し、太字、取り消し線、リンク、記事リンク、箇条書き、番号、チェックリスト、引用、コード、コードブロック、表、画像）
  11. 管理者の方へ（**管理者にだけ表示**）：招待メールの送信・再送・取り消し、再設定メール、権限変更・無効化、所有者は外せないこと、ごみ箱、タグの管理
- 冒頭に目次（各節へのページ内リンク）。記法の節のアンカーは `#markdown`
- 入口：
  - 上のナビに「ヘルプ」（「記事」と「管理」の並び）
  - 編集画面の書式ボタンの並びの端に「書き方」リンク。`/help#markdown` を**新しいタブ**で開く（書きかけを失わないため）
  - 招待から登録した直後の記事一覧に「ようこそ。はじめての方は〈ヘルプ〉をどうぞ」の一言（閉じられる。保存はせず、その画面を離れたら出ない）
  - ログイン画面の案内欄に「使い方は〈ヘルプ〉」
- 文言は画面上のボタン名と同じ言葉を「」で囲んで使う。です・ます調

## わたしの判断（直してよい）

- `/help` は**ログインなしでも見られる**ようにする。中身は機能の説明だけで秘密はなく、ログイン画面・招待画面から開けると便利なため。未ログイン時は上のナビなしの簡単な枠で表示し、「管理者の方へ」は出さない
- 登録直後の一言は react-router の `navigate` の state で渡す（サーバーにもブラウザにも保存しない）
- スクリーンショットは入れない（画面を変えるたびに古くなるため）。ボタン名を文字で書く

## 作る人に任せること

- 見た目（既存の `styles.css` に合わせる）、表の組み方、各節の細かい言い回し
- 記事リンクの例の表示（`renderMarkdown` の出力そのままでよい。リンク先の有無の色分けは不要）

## テスト

- UI テスト（`src/__tests__/`）：節の見出しがそろっている、「管理者の方へ」は管理者にだけ出る、記法の表の表示側が `renderMarkdown` の結果になっている、未ログインでも表示できる
- 登録直後の一言が出る／ふだんは出ない

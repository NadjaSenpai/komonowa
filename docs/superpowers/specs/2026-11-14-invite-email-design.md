# 招待・パスワード再設定をメールで送る（短い設計）

## 目的

今は管理者が招待リンク・再設定リンクを画面で受け取り、自分で本人に渡している。リンクは一度しか表示されないため、届いたと確かめるまで画面を開いておく必要がある。Workers Paid にしたことで Cloudflare Email Sending が使えるようになったので、komonowa が本人に直接メールで送る。

## 決めたこと

- **メールだけで送る。画面にリンクは出さない**。API の応答からもトークンを外す（`{ expiresAt }` だけ返す）。
- **パスワード再設定もメールで送る**。宛先は本人の登録アドレス、有効期限は今と同じ 24 時間。
- **先に送り、送れたら記録する**。送信に失敗したら D1 には何も書かず 502「メールを送れませんでした…」を返す。前に出した未使用の招待・再設定リンクはそのまま有効。
  - 送信後に D1 への書き込みが失敗すると、届いたリンクは使えない。管理者にはエラーが出るので、送り直してもらう（まれな場合として受け入れる）。
- **再送**：招待一覧の「未使用」「期限切れ」の行に「再送」ボタン。同じアドレス・同じ権限・同じ長さの期限（`expires_at - created_at` を時間に丸める）で `POST /api/admin/invites` を呼ぶ。既存の「同じアドレスの未使用の招待は置き換える」動作で古いリンクは無効になる。新しい API は増やさない。
- **送信元**：`wrangler.jsonc` の `vars.MAIL_FROM`（`komonowa@nadja.dev`）、表示名は `komonowa`。
- **リンクのドメイン**：リクエストの URL のオリジン（管理画面を開いているドメイン）。今のクライアント側の `location.origin` と同じ考え方。
- **メールの中身**：文字だけ（`text`）。
  - 招待：件名「komonowa に招待されました」。招待した人の名前、リンク `<origin>/invite#<token>`、期限、権限、「心当たりがなければこのメールは無視してください」。
  - 再設定：件名「komonowa のパスワード再設定」。リンク `<origin>/reset#<token>`、期限（24 時間）、同じ無視の一文。

## やり方の比較

- **採用：Workers の `send_email` バインディング**（`env.EMAIL.send()`）。API トークンが不要で、「秘密の値は SETUP_TOKEN だけ」を守れる。
- 不採用：外部メールサービス（Resend など）や Cloudflare REST API。どちらも API キーという新しい秘密の値が要る。

## 制約・前提

- Email Sending は Workers Paid のみ（月 3,000 通込み）。`nadja.dev` は送信元ドメインとして登録済み（`cf-bounce.nadja.dev` の MX/SPF/DKIM を確認済み）。
- `wrangler dev` とテストでは送信は模擬され、本物は送られない。テストは送信関数をスパイしてメール本文からトークンを取り出す。
- 宛先が未確認アドレスでも届くかは、ドキュメントの記述が食い違っているため、デプロイ後に実際の 1 通で確かめる。

## 作らないもの

- HTML メール、メールのテンプレート編集、送信履歴の保存、ユーザー自身による「パスワードを忘れた」申請。

# 退会と強制退会 設計

## 目的

- **強制退会**：abuse する人を外せるようにする。今の「無効化」では、名前が記事に出続け、同じメールアドレスでまた招待されて戻ってこられる。それを防ぐ
- **退会**：本人の希望で、自分の個人情報（名前・メールアドレス・アイコン・パスワード）を消せるようにする

どちらも、書いた記事と履歴は残し、名前を「（削除されたユーザー）」と表示する。

## ゴール / ゴールでないもの

- ゴール：退会・強制退会した人の名前・メールアドレス・アイコン・パスワードが消え、記事・履歴・添付・一覧では「（削除されたユーザー）」と出る。戻せない
- ゴール：強制退会したメールアドレスは、招待もメールアドレスの変更先にもできない
- ゴールでない：その人が書いた記事や添付の削除（必要なら管理者がふだんの削除で行う）、退会の取り消し、IP などでの締め出し
- 失敗とみなすもの：退会した人がログインできる・セッションが残る。どこかの画面や API に元の名前・メールアドレスが残る。所有者や最後の管理者がいなくなる。強制退会のためにメールアドレスそのものを保存する

## 方式

利用者の行は記事・履歴・添付・共有・招待から参照されているので、**行は残して中身を消す**（匿名化）。行を消して参照を一人の「削除されたユーザー」に付け替える案は、誰が何をしたかの区別が消え、移し替えも大がかりになるので採らない。表示だけ変えて情報を残す案は、個人情報を消す目的に合わないので採らない。

## 決めたこと

- **データ**（マイグレーション `0010`）
  - `users.deleted_at INTEGER`（NULL でなければ退会済み）
  - `blocked_emails(email_hash TEXT PRIMARY KEY, created_at INTEGER NOT NULL)`。強制退会したアドレスの SHA-256（小文字にしてから）だけを持つ。アドレスそのものは残さない
- **退会・強制退会でやること**（共通、1 回の batch）
  - `name` を「（削除されたユーザー）」、`email` を `deleted-<id>@deleted.invalid`、`password_hash` を使えない値、`avatar_id`・`avatar_type` を NULL、`status` を `disabled`、`is_owner` を 0、`role` を `member`、`deleted_at` を今
  - セッション・未使用の再設定リンク・メールアドレス変更の申し込みを消す
  - その人が始めた共有を止める（行を消す）。その人が送ったまだ使われていない招待を取り消す
  - アイコン画像を R2 から消す（batch の後）
- **退会**（本人）：`POST /api/auth/withdraw` `{ currentPassword }`
  - パスワード違いは 403「現在のパスワードが正しくありません」
  - 所有者は 409「所有者は退会できません。先にほかの管理者に所有者を譲ってください」
  - 自分が最後の有効な管理者なら 409「有効な管理者が1人以上必要です」
  - 成功したらセッションのクッキーを消して `{ ok: true }`。メールアドレスは記録しないので、あとでまた招待できる
- **強制退会**（管理者）：`POST /api/admin/users/:id/remove`
  - 自分自身は 400「自分は強制退会できません。退会はアカウント画面から行ってください」
  - 所有者は 403「所有者は強制退会できません」
  - 退会済みは 404
  - 無効化済みの人も強制退会できる
  - アドレスのハッシュを `blocked_emails` に入れる
  - 管理者を強制退会して有効な管理者が 0 人になる場合は 409（実際には自分が残るので起きないが、条件付きで守る）
- **締め出し**：招待（送信・再送）と、メールアドレス変更の申し込みで、宛先が `blocked_emails` にあれば 409「このメールアドレスは使えません」。解除の画面は作らず、運用メモに解除のコマンドを書く
- **表示**
  - 名前は DB の値が「（削除されたユーザー）」になるので、記事・履歴・一覧・共有・添付は手を入れずにそう出る
  - アイコンは、退会済みなら頭文字ではなく無地（「（」が出ないように）
  - 管理画面のメンバー一覧から退会済みの人を除く。招待一覧などの「発行者」は「（削除されたユーザー）」と出る
- **画面**
  - アカウント画面の最後に「退会」節：説明（「名前・メールアドレス・アイコン・パスワードが消え、記事と履歴は『（削除されたユーザー）』の名前で残ります。取り消せません」）、現在のパスワード、「退会する」（確認あり）。所有者には「所有者は退会できません」とだけ出す。退会したらログイン画面へ
  - 管理画面のメンバーの操作に「強制退会」（所有者と自分には出さない）。確認：「〇〇 さんを強制退会しますか？名前・メールアドレス・アイコンが消え、同じメールアドレスでは招待できなくなります。記事は『（削除されたユーザー）』の名前で残ります。取り消せません」
- **ヘルプ・README・運用メモ**：退会・強制退会のことと、締め出しの解除コマンド

## わたしの判断（直してよい）

- 退会した人の始めた共有は止める（abuse の人が外へ出した共有を残さないため。退会も同じ扱いにそろえる）
- 自主退会のアドレスは締め出さない（本人が戻りたいときに戻れるように）
- 締め出しの解除は画面を作らずコマンドで（まれな操作のため）

## テスト

- 権限：退会は未ログイン 401。強制退会は未ログイン 401・メンバー 403
- 退会：パスワード違い 403、所有者 409、最後の管理者 409。成功するとログインできず、セッションも無効。`/api/admin/users` に出ない。記事・履歴の名前が「（削除されたユーザー）」。アイコンが R2 から消える。始めた共有が止まる。同じアドレスにまた招待できる
- 強制退会：自分 400、所有者 403、退会済み 404。成功すると上と同じに加え、同じアドレス（大文字違いも）への招待と、ほかの人のメールアドレス変更の申し込みが 409。送っていた未使用の招待が取り消される
- 退会済みの人の再有効化・権限変更は 404
